# 로컬 모델(Ollama)을 파일럿 작업자로 들이기 — 도입 근거와 실측

작성 2026-09-20 · 대상: 처음 보는 사람 · 전문 용어는 쉬운 말과 함께 씁니다.

## 왜 들였나

이 프로젝트의 실행은 두 원격 도구(Codex, Antigravity)에 의존합니다. 둘 다 **계정 사용 한도**가 있어, 2026-09-20에는 양쪽 모두 소진돼 작업이 멈췄습니다(Gemini 계열 약 65시간, Opus 약 5일, Codex는 9/24까지).

로컬 모델은 한도가 없습니다. 품질은 낮지만, 이 프로젝트에는 **약한 작업자를 안전하게 쓸 수 있는 구조**가 이미 있습니다. 복사본에서 일하고, 정해진 검사를 통과해야만 원본에 반영되며, 통과하지 못하면 아무것도 바뀌지 않습니다. 그래서 실패해도 손해는 시간뿐입니다.

## 무엇을 할 수 있고 무엇을 못 하나

| 작업 | 원격 도구 | 로컬 qwen2.5-coder 7B |
|---|---|---|
| 여러 파일에 걸친 설계·판정 | 가능 | 불가 |
| 한 파일 안 기능 구현 + 테스트 통과 | 가능 | 조건부(명세가 줄 단위로 구체적일 때) |
| 지시받은 줄 교체·상수 변경 | 가능 | **가능** |
| 원인 추론해 수정 | 가능 | 낮음 |
| 결함 스스로 발견 | 가능 | 거의 불가 |

결론: **"무엇을 어떻게 바꿀지 이미 정해진 패치를 대신 쳐 넣는 손"** 으로만 씁니다. 판정·요약·검증에는 쓰지 않습니다. 브리핑 생성에 모델을 넣으면 "같은 입력이면 같은 결과"라는 계약이 깨지고, 게이트에 모델 판단을 넣으면 거짓 성공 위험이 늘기 때문입니다.

## 어떻게 붙였나

파일럿은 작업자에게 `-p <프롬프트> --output-format json --add-dir <작업공간>`으로 말을 걸고, 작업자가 그 작업공간의 파일을 고친 뒤 JSON 한 덩어리를 돌려주길 기대합니다. `v7_harness/adapters/ollama_worker.py`가 그 규격을 로컬 모델에 맞춰 줍니다.

의도적으로 좁게 만들었습니다.

- 받아들이는 형식은 하나뿐입니다: `===FILE: <경로>===` 다음에 **파일 전체 내용**. 설명이나 조각 출력은 실패로 끝납니다.
- 작업공간 밖 경로(`../`)는 거부합니다.
- 서버가 없으면 조용히 넘어가지 않고 실패로 보고합니다.
- 과제가 가리키는 파일의 현재 내용을 함께 넣어 줍니다. 7B 모델은 파일을 스스로 찾지 못합니다.

사용법:

```bash
python -m v7_harness.cli pilot run --task T01 --source <폴더> \
  --prompt-file <할 일.md> --work-dir .work/pilot_T01 \
  --worker local --accept-cmd "<인수 검사 명령>"
```

환경변수로 조정합니다: `OLLAMA_HOST`, `OLLAMA_WORKER_MODEL`, `OLLAMA_WORKER_NUM_CTX`, `OLLAMA_WORKER_KEEP_ALIVE`.

## 실측 (n=1)

| 항목 | 값 |
|---|---|
| 설치 | Ollama v0.34.2 (winget), 모델 `qwen2.5-coder:7b` Q4_K_M |
| 하드웨어 | GTX 1660 Ti 6GB, VRAM 점유 4.3GB, 문맥 16384 |
| 과제 | 전역 규칙 승인 목록을 화이트리스트로 좁히는 4파일 패치(줄 단위 지시서 제공) |
| 결과 | `verdict_hint: PASS`, 인수 검사 통과, 4개 파일 변경 |
| 시간 | 6분 43초 (소형 과제는 1.4초) |
| 계정 한도 소모 | 0 |
| 사람 검토 | diff 확인 결과 지정한 줄만 교체, 필수 문구·제목 순서 보존 |

성공률은 1회 시도 기준이므로 `UNMEASURED`입니다. 표본이 쌓이면 갱신합니다.

## 안 하는 것

- Ollama 앱의 **Apps 화면에서 Claude Code·Codex CLI를 로컬 모델에 연결하지 않습니다.** 판정과 검증은 강한 모델이 맡아야 합니다.
- 브리핑 요약, 게이트 판정, 인수 기준 작성에 로컬 모델을 쓰지 않습니다.
