# 로컬 모델(Ollama)을 파일럿 작업자로 들이기 — 도입 근거와 실측

작성 2026-09-20 · 대상: 처음 보는 사람 · 전문 용어는 쉬운 말과 함께 씁니다.

## 왜 들였나

이 프로젝트의 실행은 두 원격 도구(Codex, Antigravity)에 의존합니다. 둘 다 **계정 사용 한도**가 있어, 2026-09-20에는 양쪽 모두 소진돼 작업이 멈췄습니다(Gemini 계열 약 65시간, Opus 약 5일, Codex는 9/24까지).

로컬 모델은 한도가 없습니다. 품질은 낮지만, 이 프로젝트에는 **약한 작업자를 안전하게 쓸 수 있는 구조**가 이미 있습니다. 복사본에서 일하고, 정해진 검사를 통과해야만 원본에 반영되며, 통과하지 못하면 아무것도 바뀌지 않습니다. 그래서 실패해도 손해는 시간뿐입니다.

## 무엇을 할 수 있고 무엇을 못 하나

| 작업 | 원격 도구 | 로컬 qwen2.5-coder 7B | 근거 |
|---|---|---|---|
| 여러 파일에 걸친 설계·판정 | 가능 | 불가 | 미측정 영역, 구조상 불가 |
| 지시받은 줄 교체·상수 변경 | 가능 | **가능** | 벤치 easy PASS (9.7초) |
| 같은 규칙을 여러 파일에 적용 | 가능 | **가능** | 벤치 medium PASS (4.8초, 2파일) |
| 설명된 결함을 코드 고쳐 수정 | 가능 | **가능(작은 범위에서)** | 벤치 hard PASS (6.9초). 빈 입력 예외 처리와 짝수 개 중앙값을 모두 정확히 고침 |
| 실제 규칙 문서 4파일 패치 | 가능 | **가능** | WL03 PASS (6분 43초, 승인·배포까지 완료) |
| 결함 스스로 발견 | 가능 | 거의 불가 | 지시 없는 탐색은 시험하지 않음 |

**이전 평가 정정**: 도입 시점에 "원인 추론해 수정: 낮음"이라고 적었으나, 벤치 hard 과제에서 두 결함을 모두 정확히 고쳤다. 작은 파일·명확한 증상 범위에서는 가능하다고 정정한다.

결론: **"무엇을 어떻게 바꿀지 이미 정해진 패치를 대신 쳐 넣는 손"** 으로만 씁니다. 판정·요약·검증에는 쓰지 않습니다. 브리핑 생성에 모델을 넣으면 "같은 입력이면 같은 결과"라는 계약이 깨지고, 게이트에 모델 판단을 넣으면 거짓 성공 위험이 늘기 때문입니다.

## 어떻게 붙였나

파일럿은 작업자에게 `-p <프롬프트> --output-format json --add-dir <작업공간>`으로 말을 걸고, 작업자가 그 작업공간의 파일을 고친 뒤 JSON 한 덩어리를 돌려주길 기대합니다. `v7_harness/adapters/ollama_worker.py`가 그 규격을 로컬 모델에 맞춰 줍니다.

의도적으로 좁게 만들었습니다.

- 받아들이는 형식은 하나뿐입니다: `===FILE: <경로>===` 다음에 **파일 전체 내용**. 설명이나 조각 출력은 실패로 끝납니다.
- 작업공간 밖 경로(`../`)는 거부합니다.
- 서버가 없으면 조용히 넘어가지 않고 실패로 보고합니다.
- 과제가 가리키는 파일의 현재 내용을 함께 넣어 줍니다. 7B 모델은 파일을 스스로 찾지 못합니다.

사용법:

```bash
python -m v7_harness.cli pilot run --task T01 --source <폴더> \
  --prompt-file <할 일.md> --work-dir .work/pilot_T01 \
  --worker local --accept-cmd "<인수 검사 명령>"
```

환경변수로 조정합니다: `OLLAMA_HOST`, `OLLAMA_WORKER_MODEL`, `OLLAMA_WORKER_NUM_CTX`, `OLLAMA_WORKER_KEEP_ALIVE`.

### 벤치 v2 — 모델 3종 × 과제 6종 (각 1회, 판정은 파일럿 인수 게이트)

| 과제 | 무엇을 보나 | 7b | 3b | qwen3.5:4b |

| easy | 상수 하나 교체 | PASS 2.9s | PASS 8.9s | PASS 81.9s |
| medium | 두 파일에 같은 규칙 적용 | PASS 4.4s | PASS 2.2s | PASS 10.7s |
| hard | 설명된 결함 2개 수정 | PASS 6.3s | PASS 2.8s | PASS 22.2s |

| ambiguous | "더 튼튼하게" 같은 모호한 지시 | PASS 3.5s | **REWORK** | PASS 17.5s |
| multi_file_refactor | 세 파일에 걸친 이름 변경 | PASS 5.2s | PASS 2.4s | PASS 28.1s |
| **합계** | | **6/6, 140.9s** | 5/6, 49.2s | 6/6, 234.0s |

**예상이 틀린 지점**: 큰 파일(483줄 전체 재작성)과 다파일 리팩터를 로컬 모델의 한계로 봤는데 셋 다 통과했습니다. 실제로 갈린 유일한 지점은 **모호한 지시**였고, 거기서 3b만 실패했습니다.

**기본 모델**: `qwen2.5-coder:7b`. 유일하게 모호한 지시까지 통과하면서 총 소요가 4b의 60% 수준입니다. 3b는 빠르지만 판단이 필요한 과제에서 무너지고, qwen3.5:4b는 정확하지만 느립니다.

### 개선: 긴 파일은 "찾아서 바꾸기" (2026-09-21)

483줄 파일에서 한 줄만 바꾸는데 전체를 다시 써서 118초가 걸렸습니다. 대상 파일이 150줄 이상이면 `===EDIT:` 블록(SEARCH/REPLACE)을 요구하도록 바꿨습니다. SEARCH가 정확히 한 번 나올 때만 적용하고, 0번(원문을 잘못 옮김)이나 2번 이상(어디를 바꿀지 모호)이면 추측하지 않고 실패합니다. 여러 편집 중 하나라도 실패하면 어느 파일도 바뀌지 않습니다.

| 모델 | large_file 전 | 후 | 출력 토큰 |
|---|---|---|---|
| qwen2.5-coder:7b | 118.6초 | **30.2초 → 15.8초**(재측정) | 29 |
| qwen2.5-coder:3b | 30.5초 | **13.9초** | 29 |

7b 전체 6과제: 6/6 통과, 총 **140.9초 → 48.5초(−66%)**. 짧은 파일 과제는 종전대로 전체 재작성을 써서 결과가 같습니다.

## 실행 전 조언 (`worker_advice`)

벤치에서 실패 축이 모호함 하나로 드러났으므로, 파일럿 실행 시 지시문의 **구체성**을 0~100으로 재어 작업자를 권합니다. 막지는 않고 한 줄만 알립니다.

| 신호 | 점수 |
|---|---|
| 대상 파일을 이름으로 지목 | +25 |
| 바꿀 값·이름 명시(`from 30 to 90`) | +15 |
| 구체적 동작 동사 또는 기대 결과 명시(`must … instead`) | +15 |
| 요구사항을 번호로 나눔 | +10 |
| 코드·예시 블록 | +10 |
| "적절히·개선·robust" 등 판단을 넘기는 표현 | −25 (개당) |

60점 이상이면 `local`, 미만이면 `agy`를 권합니다. 기준선은 벤치 6과제의 실제 결과이며, 테스트가 그 대응을 고정합니다(로컬이 통과한 5과제는 `local`, 실패한 1과제는 `agy`로 나와야 통과).

**한계**: 재는 것은 문장의 구체성이지 개념적 난이도가 아닙니다. 구체적으로 적힌 어려운 설계 과제도 높은 점수를 받습니다. 실제로 R2 위임 문서는 95점이지만 그 과제를 로컬로 돌려 본 적은 없습니다(`UNKNOWN`).

## 안 하는 것

- Ollama 앱의 **Apps 화면에서 Claude Code·Codex CLI를 로컬 모델에 연결하지 않습니다.** 판정과 검증은 강한 모델이 맡아야 합니다.
- 브리핑 요약, 게이트 판정, 인수 기준 작성에 로컬 모델을 쓰지 않습니다.
