# 08. 비판적 재검토 — 아직 약한 곳과 우선순위 (2026-09-25)

- 이 장은 **작성자(Claude)가 자기 작업을 다시 공격해 본 결과**다. 자기 검토에는 한계가 있으므로 최종 판정은 Codex가 한다(04장 "자기 선호 편향").
- 읽는 법: 위쪽일수록 급하다. 각 줄에 "어떻게 확인하나"가 있으니 직접 확인할 수 있다.

## 1. 이번 재검토에서 찾아서 바로 고친 것

| # | 약점(쉬운 말) | 왜 위험했나 | 어떻게 찾았나 | 조치 |
|---|---|---|---|---|
| R1 | 같은 작업을 재실행해 생긴 행을 **표본 여러 개로 셌다** | 작업 1개만으로 "표본 3개 이상" 관문을 통과한다. 자가개선이 속기 쉬운 길이다 | 전·후 작업을 각 1개씩, 3번씩 재실행한 장부를 관문에 넣었더니 `ADOPT_CANDIDATE`가 나왔다 | 작업 ID당 마지막 실행 한 행만 센다. 후보 목록에 같은 ID가 두 번 있으면 `DUPLICATE_WORK_IDS`로 거부. 테스트 `test_a_retried_task_counts_once`(수정 전 실패) |
| R2 | 채택한 변경의 재검증을 **아무 작업자의 실행으로나** 채웠다 | Ollama 매뉴얼 개선이 Ollama와 무관한 apply 실행 10번만으로 "재검증 완료"가 된다 | 재검증 조건을 다시 읽다가 발견 | 변경 대상 작업자의 실행만 센다. 채택 뒤 수치(`since`)를 채택 전(`before`)과 나란히 보여 준다. `test_one_change_per_window`에 반례 추가 |

## 4. 이 재검토의 방법 (다음 사람도 똑같이 하라고)

1. 내가 만든 관문에 **통과하면 안 되는 입력**을 넣어 본다. 재실행 복제, 다른 작업자 섞기, 자기 서명 같은 것들이다.
2. 문서의 "됐다" 문장마다 **증거 칸**이 채워져 있는지 본다. 비어 있으면 `UNKNOWN`으로 바꾼다.
3. 다른 환경(Windows)과 다른 사람(Codex)의 결과를 기다린다. 기다리는 동안 유료 모델로 폴링하지 않는다. 결과는 PR 알림과 우편함으로 온다.
