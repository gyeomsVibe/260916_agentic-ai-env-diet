## 1. 한 줄 정의

**Ollama는 내 컴퓨터 안에서 언어 모델을 돌려 주는 프로그램**입니다. 인터넷 너머 회사 서버 대신 내 GPU와 메모리를 쓰므로, 사용 한도도 없고 요금도 없습니다. 대신 성능은 내 하드웨어만큼입니다.

---

## 2. 구조: 세 덩어리

```
[ 명령어 ollama ]  ──HTTP──▶  [ 서버 ollama serve ]  ──▶  [ 추론 엔진(llama.cpp 계열) ]
     CLI                       127.0.0.1:11434                  GPU/CPU에서 실제 계산
                                     │
                                     ▼
                          [ 모델 저장소 blobs + manifests ]
```

1. **CLI**: `ollama run`, `ollama pull` 같은 명령. 실제 계산은 하지 않고 서버에 요청만 보냅니다.
2. **서버**: 기본 주소 `http://127.0.0.1:11434`. 요청을 받아 모델을 메모리에 올리고 답을 만들어 돌려줍니다. 우리 프로젝트는 CLI를 거치지 않고 **이 서버에 직접** 요청합니다.
3. **추론 엔진**: 모델 가중치를 GPU 메모리(VRAM)에 올려 놓고 토큰을 하나씩 만들어 냅니다.

---

## 3. 모델은 어떻게 저장되나

Ollama는 모델을 도커 이미지처럼 **내용 주소(content-addressed)** 방식으로 보관합니다. 같은 내용은 한 번만 저장되고, 여러 모델이 같은 조각을 공유할 수 있습니다.

- `manifests/…/qwen2.5-coder/7b` — 이 모델이 어떤 조각으로 이루어졌는지 적은 목록
- `blobs/sha256-…` — 실제 조각 파일들

이 PC의 `qwen2.5-coder:7b` 실측 구성:

| 조각 | 크기 | 무엇 |
|---|---|---|
| model | 4,683 MB | 가중치(실제 지능이 담긴 숫자 덩어리) |
| template | 0.0 MB | 프롬프트를 모델이 기대하는 형식으로 감싸는 틀 |
| system | 0.0 MB | 기본 시스템 지시문 |
| license | 0.0 MB | 라이선스 |

저장 위치는 환경변수 `OLLAMA_MODELS`로 지정합니다(이 PC는 `D:\AI-Models\Ollama`, 총 10GB).

---

## 4. 왜 7B 모델이 4.7GB인가 — 양자화(quantization)

원래 이 모델의 숫자는 하나에 16비트(2바이트)입니다. 76억 개면 약 15GB라 6GB GPU에 올라가지 않습니다.

**양자화**는 그 숫자들을 더 적은 비트로 줄여 저장하는 기법입니다. 이 PC의 모델은 `Q4_K_M`, 즉 대부분을 4비트 근사로 저장합니다.

| | 크기 | 6GB GPU |
|---|---|---|
| 원본 16비트 | 약 15GB | 불가 |
| **Q4_K_M(현재)** | **4.7GB** | **가능** |

대가는 정확도가 조금 떨어지는 것입니다. 줄 교체나 작은 수정에는 문제가 없고, 복잡한 추론에서 차이가 납니다.

---

## 5. 답을 만드는 과정

```
프롬프트 → 토큰으로 쪼갬 → 28개 층을 통과시켜 다음 토큰 예측 → 한 글자씩 이어 붙임 → 완성
             (tokenize)        (이 모델: 28 block, 헤드 28/KV 4)
```

- **문맥 창(context window)**: 한 번에 기억할 수 있는 길이. 이 모델은 최대 32,768 토큰이고, 우리는 16,384로 씁니다. 길수록 메모리를 더 먹습니다.
- **VRAM 점유**: 실측 4.28GB / 6GB. 가중치 대부분이 GPU에 올라가고 나머지는 CPU가 맡습니다.
- **`keep_alive`**: 모델을 메모리에 얼마나 붙잡아 둘지. 우리는 30분입니다. 처음 부를 때는 로딩에 1분 넘게 걸리고, 올라가 있으면 몇 초 만에 답합니다(실측: 첫 호출 77초 → 이후 1.4초).

## 6. 우리가 쓰는 API

CLI를 거치지 않고 서버에 직접 요청합니다. CLI를 쓰면 프로세스를 새로 띄우는 비용이 붙고 오류 처리가 어렵기 때문입니다.

| 주소 | 쓰임 |
|---|---|
| `POST /api/generate` | 프롬프트 하나를 주고 답을 받음 (우리 작업자가 쓰는 것) |
| `GET /api/tags` | 받아 둔 모델 목록 |
| `GET /api/ps` | 지금 메모리에 올라가 있는 모델과 VRAM 점유 |
| `POST /api/show` | 모델 구조와 양자화 정보 |
| `POST /api/embed` | 문장을 숫자 벡터로 (검색·유사도용) |

우리 요청의 고정값과 이유:

| 값 | 설정 | 왜 |
|---|---|---|
| `temperature` | 0.1 | 이 작업자는 창작이 아니라 지시받은 줄을 옮기는 손입니다. 무작위성이 낮아야 합니다. |
| `num_ctx` | 16384 | 파일 전체를 넣어야 하므로 넉넉히, 그러나 6GB에 맞게. |
| `keep_alive` | 30m | 연속 작업에서 매번 로딩하지 않기 위해. |
| `stream` | false | 파일럿은 완성된 답 한 덩어리를 기대합니다. |

## 7. 이 프로젝트에 붙는 자리

```
파일럿(pilot) ──▶ 작업자 ──▶ 복사본(staging)의 파일 수정 ──▶ 인수 검사 ──▶ 통과해야 반영
                   ↑
      agy(원격, 계정 한도) 또는 local(Ollama, 한도 없음)
```

- 선택: `python -m v7_harness.cli pilot run … --worker local`
- 어댑터: `v7_harness/adapters/ollama_worker.py`
- 받아들이는 응답 형식은 하나뿐입니다: `===FILE: <경로>===` 다음에 **파일 전체 내용**. 설명이 섞이면 실패로 끝납니다. 약한 모델일수록 형식을 좁혀야 판정이 단순해집니다.
- 작업공간 밖 경로(`../`)는 거부하고, 서버가 없으면 조용히 넘어가지 않고 실패로 보고합니다.

**쓰지 않는 자리**: 판정, 브리핑 요약, 인수 기준 작성. 판정에 모델 판단이 끼면 거짓 성공을 막을 수 없고, 브리핑에 끼면 "같은 입력이면 같은 결과"라는 계약이 깨집니다.

## 8. 운영 명령

```bash
# 서버 상태와 올라간 모델
curl http://127.0.0.1:11434/api/ps

# 받아 둔 모델 목록
ollama list

# 모델 받기 / 지우기
ollama pull qwen2.5-coder:7b
ollama rm <모델>

# 조정 (환경변수)
OLLAMA_HOST, OLLAMA_MODELS, OLLAMA_WORKER_MODEL, OLLAMA_WORKER_NUM_CTX, OLLAMA_WORKER_KEEP_ALIVE
```
