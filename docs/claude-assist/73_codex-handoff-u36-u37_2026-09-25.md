## 3. 설계 결정과 이유 (반박하려면 여기)

- **관문이 수치를 다시 계산**: 후보에 `before`/`after` 수치가 있으면 `SELF_REPORTED_METRICS`로 거부한다. 작업 ID만 받아 장부에서 계산한다. DGM·METR 사례처럼 작성자가 점수를 만들어 넣는 경로를 없애기 위해서다.
- **한 번에 1개**: 채택 시 `recheck_at_rows = 현재 행 + window`를 기록한다. 그 전에 두 번째 채택이 오면 `ONE_CHANGE_PER_WINDOW`로 거부한다. docs/31 §4의 "개선안은 최대 1개씩"을 코드로 옮긴 것이다.
- **교환원의 RSI 역할**: 관찰 트리거만 맡는다. 메시지 ID는 `rsi_review_<worker>_<window>x<n>`이고, 확인(ack) 뒤에도 같은 ID는 재발행하지 않는다(우편함 ID 규칙). P1이 아니므로 벨을 울리지 않는다.
- **`--from-hook`은 항상 exit 0**: Claude UserPromptSubmit 훅이 exit 2를 내면 질문이 막힌다. 출력은 세 가지다.
  - SessionStart: 한 줄(맥락 비용 최소).
  - UserPromptSubmit: 없음(질문마다 붙으므로).
  - Antigravity: `{}`(결과를 JSON으로 읽음).
- **프로젝트 찾기 순서**: 훅 입력의 `cwd`·`workspacePaths` → `CLAUDE_PROJECT_DIR` → 현재 폴더 순이고, 각 후보에서 상위로 올라가며 `.coord/PLAN.md`를 찾는다. Antigravity가 훅을 `~/.gemini/config`에서 실행하는 문제(antigravity-cli#1005) 때문이다.
- **교환원 단일 실행**: `<프로젝트>/.work/sentinel/loop.pid`에 살아 있는 PID가 있으면 `ALREADY_RUNNING`으로 끝난다. 로그온 작업과 수동 실행이 겹치는 경우에 대비한 것이다.
- **Windows 셸(Codex 67a1539 지적 반영)**: 설치기 훅 명령은 슬래시 경로·조건부 따옴표로 써서 bash·cmd·PowerShell에서 같은 명령이 돈다. 이 저장소 `.claude/settings.json`은 Claude 기본 셸(bash, Windows는 Git Bash)을 전제로 `cd "$CLAUDE_PROJECT_DIR" && python -m …`를 유지했다. 사용자 PC의 Claude가 PowerShell 훅 셸을 쓰면 `settings.uaos-windows-proposed.json` 형식으로 바꿔야 한다(판정 요청).
- **이 세션 자신**: 프로젝트 설정의 `send_later` 차단 때문에 PR 확인 예약을 쓰지 않는다. PR 감시는 GitHub 이벤트로만 한다.
