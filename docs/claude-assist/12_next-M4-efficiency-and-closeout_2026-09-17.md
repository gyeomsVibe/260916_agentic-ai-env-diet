# 지시 12 — 다음 단계: M4 효율 튜닝 + 마감 정리 (Codex 조율자에게)

## 왜 이것이 다음인가

- 사용자 제안의 최우선 목적은 **"Codex 사용량을 살리고 Antigravity 사용량으로 대신 완수하는 예산절약 결과주의"(R07·R08·R09)** 다.
- M1~M3로 경로는 완성됐다. 그러나 P01 A/B 실측(`.coord/runs/P01/ab.json`)에서는 목적이 아직 **수치로 확인되지 않았다.**
  - A(Codex 단독): 5h 창 +2%p, 23.2초
  - B(Codex+Antigravity): 5h 창 +8%p, 146.7초(성공 실행만 68.9초), Codex 판정 2턴
- 따라서 다음 단계는 새 기능이 아니라 **B 경로에서 Codex 소모를 줄이고, 효과가 드러나는 과제 크기로 다시 측정하는 것**이다.

## [M4] 효율 튜닝 — 범위와 순서 (종료 규칙 docs/15 §3 동일)

1. **Codex 소모 원인 분해(측정만):** P01 B에서 Codex가 쓴 턴·읽은 파일·출력 길이를 세션 로그로 집계해 `.coord/runs/M4/codex-cost-breakdown.md`에 기록한다. `codex exec --json` usage를 쓸 수 있으면 토큰으로 기록한다.
2. **판정 1턴화:** `pilot run` 종료 시 `summary.json`에 `verdict_hint`(PASS/REWORK/BLOCKED)와 인수 테스트 exit를 넣는다. Codex는 **summary 1회 읽기 + 판정 1턴**만 하도록 프로젝트 `AGENTS.md`에 한 줄로 고정한다. 인수 테스트 명령은 `--accept-cmd` 인자로 받아 staging에서 pilot이 직접 실행한다.
3. **실패 재실행 비용 제거:** 첫 실행이 외부 쓰기 감시에 막힌 원인(TEMP 잡음)은 이미 해소됐다. 같은 원인이 재발하면 자동 재실행하지 않고 즉시 BLOCKED로 요약한다.
4. **재측정 P03:** 효과가 드러나는 중형 과제로 A/B를 다시 한다. 예: 샘플에 모듈 2개와 테스트 10개 이상 추가. A와 B 폴더를 분리하고 같은 프롬프트를 쓴다. 지표: Codex 5h%·턴·토큰, agy usage, 벽시계, 인수 exit, 재작업 수.
5. **게이트:** 품질 동등(인수 통과)이면 채택한다. Codex 사용량 변화는 실측값 그대로 보고한다. 목표 수치는 강제하지 않는다.
