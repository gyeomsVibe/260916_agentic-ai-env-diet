# U40 — Ollama RSI 학습·능력지도·선택적 미세조정 설계

상태: Codex 보조·감사 설계안. Claude 주도자와 독립검증을 거쳐야 정본이 된다.

## 결론

Ollama와 대화를 반복하거나 같은 실패를 다시 시키는 행위는 모델 가중치를 바꾸지 않는다. 이것은 실행 중 자기수정(test-time refinement)이지 영구 학습이 아니다. UAOS의 RSI는 먼저 **시스템 수준 학습**으로 구현한다. 즉 실패를 기록해 다음 라우팅·매뉴얼·프롬프트·검증기를 개선한다. 모델 가중치 변경은 검증된 정답 데이터가 충분할 때 별도 LoRA/QLoRA 훈련으로만 수행한다.

## 학습 4층

1. **즉시 수정**: 한 실행 안에서 형식만 고친다. 세션이 끝나면 모델은 배우지 않는다.
2. **운영 기억**: 실패유형, 좋은 예시, 프롬프트, 라우팅 규칙을 저장해 다음 호출에 넣는다. 가중치는 그대로지만 UAOS는 실제로 개선된다.
3. **능력지도**: 모델·버전·설정·작업군별 성공률, 토큰, 시간, 실패원인을 측정해 Ollama가 잘하는 범위만 자동 선택한다.
4. **선택적 미세조정**: 반복되는 좁은 실패군에 검증된 정답쌍이 충분할 때 외부 훈련도구로 LoRA/QLoRA 어댑터를 만든 뒤 Ollama에 새 버전으로 가져온다.

## 실패 1건을 학습자료로 만드는 계약

각 사례는 아래를 모두 가져야 한다.

- `case_id`, `task_family`, 원본 입력 해시, 모델 이름·digest, Ollama 버전, 하드웨어
- 프롬프트·매뉴얼 해시, 온도·seed·context·출력한도
- 원출력, 실패유형(`FORMAT`, `SEMANTIC`, `UNSUPPORTED`, `SCOPE`, `TOOL_LIMIT`)
- 결정적 인수결과와 독립검증자
- 사람이 쓰거나 결정적 도구가 만든 정답(gold answer)
- 토큰·시간·재시도 수, Antigravity 승격 여부와 결과

비밀, 사용자 개인정보, 숨은 인수 원문, 검증되지 않은 모델 자기답변은 학습자료에서 제외한다.

## 100% 파악 대신 운용범위 지도

작업군은 최소 다음처럼 분리한다: 정형추출, 고정형식 변환, 요약, 단일파일 기계편집, 다중파일 편집, 오류진단, 설계판단. 같은 모델이라도 작업군마다 다른 도구로 취급한다.

- 탐색: 작업군별 10개로 큰 결함을 찾는다.
- 후보평가: 작업군별 30개로 라우팅 후보를 비교한다.
- 운영주장: 손대지 않은 보류세트 100개를 사용한다. 100/100이어도 일반적 100%가 아니라, 실패 0건일 때의 간단한 rule-of-three로 약 95% 신뢰 실패율 상한이 약 3%라는 뜻이다.
- 실패율 1% 미만을 같은 방식으로 주장하려면 실패 0건 기준 약 300개의 독립 보류사례가 필요하다.
- 모델 digest, Ollama 버전, 프롬프트 해시, 하드웨어 또는 설정이 바뀌면 해당 지도는 새 버전으로 다시 측정한다.

## RSI 승격 루프

1. 관찰: 실제 작업 실패를 장부에 남긴다.
2. 군집화: 같은 실패원인의 사례를 묶는다. 모델 출력 자체가 아니라 인수결과가 라벨이다.
3. 가장 싼 수정: 결정적 도구 → 프롬프트/예시 → RAG/메모리 → 라우팅 순으로 시험한다.
4. 고정 보류세트 A/B: 기존 버전과 후보를 같은 입력·seed·출력한도로 비교한다.
5. 채택조건: P1 0건, 핵심 통과율 비열화 없음, 목표 작업군 개선, 토큰·시간 3배 회귀 없음.
6. 그림자 운용: 실제 반영 없이 새 후보가 낼 답만 20건 기록한다.
7. 승격: `ollama-uaos-<family>-vN`처럼 새 태그로만 배포한다. 기존 태그는 롤백용으로 보존한다.

## 실제 가중치 학습을 시작하는 조건

모든 실패마다 훈련하지 않는다. 좁은 작업군 하나에서 독립검증된 정답쌍 100개와 손대지 않은 보류사례 30개가 모였을 때만 첫 LoRA 실험을 연다. 이는 보편적 과학 기준이 아니라 이 프로젝트의 초기 데이터품질 관문이다. 표본이 적으면 프롬프트·RAG가 더 싸고 안전하다.

- 훈련은 Ollama 안에서 하지 않는다. Hugging Face TRL/PEFT 같은 외부 도구로 LoRA/QLoRA를 학습한다.
- 현재 PC는 GTX 1660 Ti 6GB다. 7B 훈련 가능성을 가정하지 않는다. 먼저 0.5B~3B 후보의 메모리·시간 벤치를 하고, 실패하면 CPU 오프로딩 또는 별도 훈련환경을 검토한다.
- 학습된 Safetensors/GGUF 가중치는 Ollama `Modelfile`의 `FROM`으로 새 모델에 가져온다.
- 원 모델 출력만 다시 먹이는 순환학습은 금지한다. 원문·사람 정답·결정적 인수로 검증된 자료를 유지한다.
- 범용 모델 하나를 계속 덮어쓰지 않는다. 작업군별 어댑터/모델 태그를 분리해 망각과 회귀를 격리한다.

## 재교육의 값어치 판정

`학습가치 = 반복절감시간 × 예상반복횟수 - 데이터정제시간 - 훈련시간 - 검증시간 - 회귀위험`

- 높은 가치: 동일한 좁은 기계작업이 반복되고 정답을 자동검증할 수 있음.
- 낮은 가치: 요구가 계속 바뀜, 표본이 적음, 정답이 주관적임, Antigravity가 한 번 처리하면 끝나는 일.
- 즉시 중단: 보류세트 저하, P1 발생, 훈련자료 출처 불명, 비용 3배 회귀.

## 현재 환경 판정

- 시스템 수준 RSI: **지금 가치 있음**. 장부·실패분류·프롬프트·라우팅 개선을 즉시 축적한다.
- Ollama 가중치 미세조정: **아직 데이터 부족으로 보류**. 현재 장부는 테스트 오염과 검증누락이 있어 훈련용 정답세트가 아니다.
- 다음 구현: 정답사례 스키마와 능력지도 리포트를 먼저 만든다. 10개 유효 사례마다 프롬프트/라우팅 개선을 검토하고, 100개 검증쌍 전에는 모델훈련을 시작하지 않는다.
